# Changelog

## v0.2.0 (unreleased)

Weft's inputs model grows up — four declared ways for a component to get what it needs (`param`, `receives`, `derives`, `defines`), values that flow down the render tree, and `closest` / `enclosing` to reach back up it — alongside typed wire params, one-call Zeitwerk-powered app loading, live streams that heal themselves, not-found pages you can finally brand, and DSL vocabulary renames (`attribute` → `param`, `shorthand` → `preset`).

### New Features:

- **Self-Healing Live Streams** – `recovers` now protects SSE pushes the way it protects every other render: when a push fails, the stream delivers your recovery component's content in place of the frame, walked from the same chain (entries targeting a Page are skipped — a stream can't redirect — and the gem-default error component always waits at the bottom). And a stream that keeps failing no longer errors forever: after a budget of consecutive failures, Weft pushes a final frame, tells the browser to stop reconnecting, and closes the connection — a durably broken component costs a bounded number of attempts instead of an infinite error loop.
  - **Countdown-aware error UI** – Recovery components can declare `param :attempts_remaining` (a new auto-injected recovery param, present only on the push path) to tell "still retrying" apart from "gave up": it counts down to 0 on the final frame. The gem-default error component uses it out of the box — "Live updates interrupted" while attempts remain, "Live updates stopped" with a resume button on the last frame.
  - **One-Click Resume** (`reopen_stream:`) – The new preset sibling of `retry:`: `button "Resume live updates", reopen_stream: @params.retry_url` re-fetches the component whole, and the fresh render reopens the stream with a full budget. Same URL value as `retry:`, aimed at the stream wrapper instead of the error box — and like every preset, no hand-written htmx.
  - **A Budget You Control** – Set the gem-wide default with `Weft.configure { |c| c.push_attempts = 5 }` (default 3) or per component with `pushes every: 5.seconds, attempts: 5`; a successful push resets the count.
  - **Frames That Mirror Normal Pushes** – Recovery frames ship exactly like healthy ones (the component's interior, swapped into the persistent wrapper), so error styling belongs on inner elements — the gem default and its extension pattern both do this. Every pushing component's wrapper now carries `sse-close`, the attribute htmx's SSE extension honors when the server signals the close.

- **First-Frame Timing for Streams** (`pushes immediate: false`) – Live streams send every new subscriber an immediate snapshot frame by default, so a freshly loaded page never sits empty waiting for the cadence. When that snapshot would mislead — the state it shows is only meaningful once a push cycle has computed it — `immediate: false` waits one full interval before the first frame, restoring polling-cadence semantics for exactly the components that want them.

- **Caller Hand-Offs** (`receives`) – Give a component a rich object a URL can't carry — a record, a computed value, a built collection. `receives :order` makes `order_row(order: order)` fill `params.order`, and the kwarg never leaks onto the wrapper as an HTML attribute. A missing required hand-off raises `Weft::NotReceived` pointing at the call site; add a default (`receives :page_num, default: 1`, even an explicit `default: nil`) to make it optional. Hand-offs stay server-side — they never serialize into a URL, and declaring one doesn't make a component routable. This replaces the v0.1 pattern of pulling rich objects out of `attributes` before `super`.
  - **Dual-source keys** – Declare both `param :status` and `receives :status` and the key gets two doors: an embedded call site hands the value over, and it serializes as a wire param too, so a standalone refresh can reconstruct it. A self-refreshing card embedded as `status_card(status: "hot")` keeps its status across refreshes.
  - **`dependent!`** – Mark a component that only makes sense inside a parent (an alias of `abstract!`): "my parent hands me this every time, so serving me standalone makes no sense."
  - **Refresh-safety lint** – At route validation, a routable component that requires a hand-off but has no wire fallback logs a warning — it renders fine embedded, but would raise on every standalone refresh. Give it a dual or mark it `dependent!`.

- **Lazy Server-Side Derivations** (`derives`) – The third door into `params`, retiring the find-by-id dance at the top of every `build`. `derives(:name) { |params| ... }` registers a block that runs at most once per render, the first time `params.name` is read — and never runs if nothing reads it. Derivations chain lazily: `derives(:order) {...}` plus `derives(:shipments) { |p| Shipment.for_order(p.order.id) }` computes exactly what a render touches and nothing more. Derived values stay server-side — never serialized, not routable-making — but they flow down the render tree like everything else, and a value an ancestor already computed isn't recomputed by a child.
  - **Pure `(params) -> value` blocks** – A derivation runs against a sandboxed `self`: `params` and lexical constants are in reach and `Kernel` stays available (`raise`, `format`, `Integer()`), but nothing component-specific is — a stray method call fails fast with `NameError`. Each block gets its own fresh, disposable context, so scratch instance variables are allowed but never outlive the one execution. A failing derivation raises at first read, inside the `recovers`-wrapped render, so `recovers from: ActiveRecord::RecordNotFound` and friends handle it like any other failure; a derivation nobody reads never raises.
  - **Duals** – `derives` + `receives` completes the parity pattern: handed the value when embedded, self-fetching when standalone. `param` + `derives` gives wire-if-present-else-derive. A `derives` dual also satisfies the refresh-safety lint.
  - **Divergence warning** – When an inherited value shadows a component's own, *different* derivation for the same key, Weft logs a one-time warning (the ancestor's value wins; a derivation shared through a mixin stays quiet).
  - **`defines key: value, ...`** – Sugar for statically-known derivations: each pair is exactly `derives(key) { value }`, with the same priority, overridability, and laziness. Values fix when the class body runs — that's the point, and the caveat: anything computed per render (a query, a clock) belongs in `derives`, because an interpolated value here would freeze at load time.
  - **Eager escape hatch** – `params.to_h` and delegated Hash-API calls materialize every remaining derivation first, when you want the whole bag at once.

- **Ancestor Navigation** (`closest` / `enclosing`) – Where params flow *down* the render tree, these reach *up* it: a nested component finds an ancestor and reads its identity, so it can target that ancestor instead of being hand-fed the details. A pager finds its enclosing panel with `enclosing(Weft::Component)` and reads the route and DOM id to aim its swaps at — no more passing `target_class` / `target_id` at every call site. `closest(matcher)` matches the DOM's `element.closest()` (self included, nearest-first, `nil` if none); `enclosing(matcher)` is the same walk strictly above self; `closest!` / `enclosing!` raise `Weft::AncestorNotFound` when a required ancestor is missing. Match by Class or Module (`is_a?`), by Symbol tag name, or refine either with a block. Callable inside `build`; see [Reaching enclosing components](docs/arbre.md#reaching-enclosing-components).

- **Branded Not-Found Pages** – `recovers from: Weft::NotFound, with: YourNotFoundPage` now works the way it was always documented: raise `Weft::NotFound` when a lookup comes up empty, and *your* branded page renders with the 404 — the v0.1 limitation where the gem-default not-found rendering could take over the response is gone. The repair reaches every 404 pathway: a component's own `Weft::NotFound` recovery now renders as the fragment it should be rather than being replaced by a full page, and when Weft mounts as middleware, a downstream app's own 404 responses pass through untouched. Routing misses still land on the gem-default not-found page, customizable via the `not_found_page` knob as before.
  - **Map Your Own Errors** (`status:`) – Recovery edges can now carry wire semantics, so your app's exceptions don't need translating into Weft's: `recovers from: ActiveRecord::RecordNotFound, with: NotFoundPage, status: 404` turns a missing record into a genuine branded 404 — response status and the `:status_code` recovery param both follow the declaration. Weft's error classes remain the built-in vocabulary when you'd rather raise the meaning directly; without a `status:`, recovered non-Weft errors report 500 as before. Only error statuses (400–599) are assignable — an invalid value fails loudly at declaration time.

- **One-Call App Loading** (`Weft.configure_autoloading`) – Point Weft at your app directories and code loading is handled: `Weft.configure_autoloading(paths: [...], inflections: { "my_ui" => "MyUI" })` puts a [Zeitwerk](https://github.com/fxn/zeitwerk) loader in charge — one constant per file, cross-file references resolving on demand, no require chains or load-order puzzles — and eager-loads everything on the spot, so every component and page is registered and routable before the first request. Call it before `Weft.configure`, and your configure blocks can reference the classes it loaded.
  - **A Development Loop That Keeps Up** (`reload: true`) – Code changes apply on the next request without restarting the server — edits, brand-new files, and deletions alike. Weft evicts each class from its route registry the instant Zeitwerk unloads it, so a deleted component's route disappears instead of lingering, and flipping a class's routability takes effect immediately. Class-valued settings (`error_page` and friends) rebind to fresh definitions after each reload, so even your branded error pages are live-editable.
  - **Bring Your Own Reloader** – The same primitives are public for hand-rolled setups: call `Weft.registry.evict(klass)` from your loader's unload hook (or `Weft.registry.clear` for a full reset), then `Weft.configuration.refresh_stale_classes!` so class-valued settings rebind.

- **Typed Wire Params** (`type:`) – Declare what a wire value *is* and it arrives that way: `param :page, type: :integer` reads `?page=2` as the Integer `2`, with `:string`, `:float`, `:boolean` (`"true"` and `"1"` map to `true`, anything else to `false`), and `:decimal` (full-precision `BigDecimal` — right for money) completing the vocabulary. No more inventing a default just to buy coercion: a typed param without one is simply `nil` when the wire says nothing. Declarations are checked on the spot — an unknown type, a stray kwarg, or a default that disagrees with the declared type fails at class-load time, not mid-request. An untyped param accepts whatever arrives, uncoerced: the right door for values that pass through as-is, like the nested hashes browsers submit for `items[widget]=2`.

- **Call-Site Wiring Overrides** (`target:` / `swap:` everywhere) – Every element kwarg that wires a request now honors per-call `target:` and `swap:` overrides: point one `action:` button's response at a different DOM location, or change how a `navigate:` re-fetch swaps in, exactly as `loads:` and the presets have always allowed. Declarations keep supplying the defaults (`performs :advance, target: "..."`); the call site gets the final word. And on an element Weft wires, `swap:`/`target:` never leak into the HTML as stray attributes — while a bare `target:` on an unwired element still means plain HTML (`a(href: ..., target: "_blank")` is untouched), and a bare `swap:` passes through with a one-time warning, suspect but not wrong.

- **Confirmation Dialogs** (`confirm:`) – Destructive and disruptive actions can demand a second thought: `button "Delete", action: :destroy, confirm: "Delete this order?"` shows the browser-native confirmation and only fires the request on OK. Works alongside any interaction kwarg — or standalone on a container, where htmx inheritance applies it to every request fired from inside. (A `prompt:` counterpart is deliberately deferred until action callables can read the typed reply.)

- **Deletions Without Ceremony** (`dismisses`) – A successful `dismisses` (or any `performs` with `swap: :delete`) now responds with an empty body: htmx removes the element on its own, so Weft no longer renders the component whose record the callable just deleted — the guard clause every delete-pattern `build` used to need is obsolete, and the dead render nobody would ever see is gone. Out-of-band `includes` companions still ride the response, so a delete can update the count beside the table it shrinks. And `dismisses` now accepts `target:`, completing its parity with the `performs` it sugars.
  - **Errors That Fit Where They Land** – A recovery fragment replacing a failing component now adopts that component's wrapper tag: a failed row delete puts an error `<tr>` where the row was — valid table content — instead of a `<div>` wedged between rows, and the same holds for every component recovery, delete-swap or not. Powered by `:component_tag`, a new auto-injected recovery param: the gem-default error components use it out of the box, and custom recovery components opt in by declaring it and returning it from `tag_name`.

- **Loud Wiring Failures** – A kwarg that is unmistakably Weft's but can't resolve now raises `Weft::InvalidUsage` with a pointed message, instead of silently rendering as a junk HTML attribute you'd only notice when clicking does nothing: a mistyped `action:` name (`action: :advnace` used to render `action="advnace"`), a `navigate:` outside any component, a `navigate:` overriding a param its component doesn't declare (only a component's own declared params survive the standalone re-fetch `navigate:` triggers), an orphaned `with:`, a non-Class `loads:`, a junk value on a preset kwarg — and a `loads:`/preset target (or `navigate:` host) that isn't routable, whose generated URL could only ever 404 at click time. Conditional call sites stay easy — a `nil` value means "not this time" and renders nothing. Preset registration gets the same care: a name that collides with Weft's own kwarg vocabulary raises at registration (`:prompt` is reserved ahead of its arrival), and one that shadows an HTML attribute registers with a warning explaining what it will intercept.

- **Declarative Page Titles** (`title`) – A page names its browser tab in the class body: `title "Orders"` for the static case, or `title { |params| "Order ##{params.order.number}" }` when the tab should name the record — the block receives the page's resolved params, so it composes with `derives` and the rest of the params system. Declare a static default on your base page and every concrete page inherits it until it declares its own; with no declaration anywhere, the tab reads "Weft". This retires the last piece of pre-`super` ceremony in page bodies — no more looking a record up early just to have its name ready for the `<head>`.

- **Inline Head Scripts** (`register_inline_js`) – The JavaScript sibling `register_inline_css` was missing: embed the snippets that don't warrant a file — an htmx config tweak, a one-line boot call — directly in the page head. Same accumulate semantics as the rest of the register_* family, and inline JS lands after the registered external scripts, so the libraries it references are already in reach.

- **Two More Semantic Triggers** (`:change`, `:click_once`) – The trigger vocabulary now covers the last interactions that forced raw htmx strings: `trigger: :change` fires when a select or checkbox changes value, and `trigger: :click_once` caps an interaction at a single firing — the right default for anything that *inserts* content rather than replacing it. The `inline_expand:` preset now bakes `:click_once` in, so an expand button can't double-insert its detail row on a repeat click, with no call-site override needed.

- **One Universe Per Request** – A response now resolves against the request's own wire params end to end, no matter how rendering flows inside it — an action re-render, a `transfers` hand-off, an error recovery. A nested component that reads `param :account_id` off the wire keeps reading it when its encloser re-renders after an action, when a transfer swaps a different component in, and when a recovery render takes over: no outer component has to know or relay what its inner pieces consume, so shared widgets stay genuinely encapsulated. Hashes returned from verb blocks — action callables, `transfers` and `includes` blocks, `recovers` adjustments — ride that universe as *overlays*: a returned value overrides the wire everywhere in the response, an explicit `nil` clears one, and a rich object (a record the callable already loaded) pre-empts matching `derives` down the tree, so nothing refetches what the request already computed.

- **Companions Inherit the Whole Picture** (`includes`) – An included companion now renders as an out-of-band–delivered *child* of the component it rides with: it sees the same request universe and inherits the primary's params — rich derived values included, so a shared `Order` is fetched once, not once per companion — and its block returns a small delta for this companion alone. Inclusions also grew context filters: `on:` accepts arrays (`on: %i[advance retreat]`), and `when: :transferred` scopes a companion to transfer arrivals; declare both for a union.

### Breaking Changes:

- **Renamed: `attribute` → `param`, `attrs` → `params`** – A component's or page's inputs are now declared with `param :name` and read back through `params` (`params.status`, `params[:page]`, `params.to_h`); the block argument to `performs`, `transfers`, `dismisses`, `recovers`, and `includes` is now `params`. Arbre's own HTML tag attributes are untouched — `build(attributes = {})`, `set_attribute`, and element hashes like `class:` and `data:` keep their names. To migrate, rename `attribute` → `param` and `attrs` → `params` across your components, pages, and verb blocks.

- **In-page param passing removed** – Components and pages now resolve their declared `param`s straight from the request's wire params (query, path, and body) at any nesting depth, so a component embedded in a page sees the same wire params the page does: call sites like `orders_panel(status: params.status, page: params.page)` collapse to `orders_panel`. A builder kwarg that names a declared param no longer fills `params` — it renders as a plain HTML attribute, with a one-time warning per class and key (param names can legitimately double as HTML attribute names, so this is a warning, not an error). Rich objects a caller wants to pass now get their own declaration, `receives` (above). Along with this change:
  - `params` resolves when a component is instantiated, so a `build` body can read it *before* calling `super` — deriving a page title from a record looked up by param, for example.
  - `Component.render` / `Page.render` kwargs are now exactly what a request's query string would carry; undeclared keys are ignored instead of becoming HTML attributes on the wrapper element.
  - `Weft::Context.new` accepts `wire_params:` to simulate request params when rendering outside the Router — the pattern for component specs.
  - In a plain `Arbre::Context`, components resolve their declared defaults (there is no wire source to read).
  - `Weft::Resolver#resolve` is now a class method (`Weft::Resolver.resolve`); `Weft::Params.extract_from` is removed.

- **The params bag flows down the render tree** – Within a single render, each component starts from a copy of its nearest ancestor component's (or page's) resolved params: it sees everything *above* it, nothing *beside* it. A bare `shipments_card` embedded in a page that declares `param :order_id` reads `params.order_id` without declaring anything. When a component declares a key of its own, its sources win in a fixed order: a handed value (`receives`) beats the component's own wire value, which beats an inherited one, which beats the component's own derivation (`derives`), which beats the declared default. Serialization is unaffected — only a component's *own* declared `param`s appear in its refresh/stream URLs and action payloads (`hx-vals`); inherited values are a delivery convenience, not part of the refresh contract. One consequence to watch: a nested component that used to fall back to its own default while an ancestor held a different value for the same name now inherits the ancestor's value.

- **Renamed: `shorthand` → `preset`; `register_css` → `register_inline_css`** – The named interaction presets — `tooltip:`, `modal:`, `lazy:`, `load_more:`, `infinite_scroll:`, `live_search:`, `tabs:`, `inline_expand:`, and `retry:` — are now registered and looked up as *presets*: `Weft::Shorthands` → `Weft::Presets`, `Weft.register_shorthand` → `Weft.register_preset`, `Weft.shorthand` → `Weft.preset`. The element kwargs themselves are unchanged — `tooltip:`, `modal:`, `lazy:` and friends work exactly as before. Separately, `Weft::Page.register_css` → `register_inline_css`, restoring naming parity with `register_stylesheet`. To migrate, rename any custom `register_shorthand` calls to `register_preset`, and `register_css` to `register_inline_css`.

- **Removed: `auto_reload` / `reload_paths`** – The Sinatra::Reloader integration is retired in favor of `Weft.configure_autoloading(reload: true)`, which reloads more of your changes (new files and deletions included) and keeps Weft's routing registry precisely in sync while it does. The `sinatra-contrib` dependency is dropped (`zeitwerk` is added). To migrate, replace the two settings with a `configure_autoloading` call naming your app directories. Reload setups that leaned on the registry's automatic stale-registration pruning now evict explicitly instead — call `Weft.registry.evict` from your reloader's unload hook; a route collision naming two same-named classes is the signal that a reload happened without it.

- **Wire coercion follows `type:`, not the default** – A param's default no longer implies its wire type: an untyped param passes its wire value through as the string it arrived as, whatever the default looks like. Declare the type you mean — `param :page, default: 1, type: :integer` — and the default must be an instance of it, checked at declaration. To migrate, add `type:` to any param whose default used to do the coercing (`default: 1`, `default: 1.5`, `default: false`); flag params especially — without `type: :boolean`, a wire `"false"` is a truthy string.

- **Destructive-swap responses are empty** – A successful delete-swap action responds `200` with no body, where it used to carry a full render htmx discarded. Out-of-band `includes` fragments still arrive; only the dead primary render is gone. If a `build` guarded against its just-deleted record solely for that render's sake, the guard can be removed.

- **Renamed: `weft_id` → `weft_dom_id`** – The method (and its class-level sibling, `weft_id_for` → `weft_dom_id_for`) names what it identifies: the component's DOM element id. The derived id *values* are unchanged by the rename, and `weft_url` keeps its name. To migrate, rename any call sites.

- **DOM ids skip unusable suffixes** – The wrapper id's suffix now rides only for non-blank scalar values (String, Symbol, number, boolean). `""` no longer leaves a trailing dash (`contact-results-`), non-scalar values no longer stringify into selector-breaking junk (`member-roster-[]` broke `querySelector`, and with it htmx targeting), and `nil` vs `""` no longer derive two different identities for the same absent value — all three now yield the bare class id. One more twin unified: `false` now suffixes exactly like `true` (`filter-card-false`), instead of silently dropping. If CSS or tests matched the old degenerate forms, update them to the bare id.

- **Non-routable load targets raise** – A `loads:` or preset kwarg naming a non-routable class, or a `navigate:` inside a component marked `abstract!`/`dependent!`, now raises `Weft::InvalidUsage` at render time. Previously the element rendered happily and the click 404'd with nothing in the logs to say why. Most targets route on their own (any param or verb infers it); mark purely presentational targets `routable!` — the error message points the way.

- **The element-kwarg surface fails loudly** – Miswired Weft kwargs that previously fell through as HTML attributes now raise `Weft::InvalidUsage` (see *Loud Wiring Failures* above), and `swap:`/`target:` alongside `action:`/`navigate:` are consumed as overrides instead of rendering as attributes. Two error classes shift with this: the `loads:`/preset "requires `swap:`/`target:`" errors now raise `Weft::InvalidUsage` where they raised `ArgumentError`, so the whole element-kwarg surface reports misuse through one class. `navigate:` override keys must be params the navigated component declares, and `Weft.register_preset` validates names (Weft's own kwarg vocabulary raises; HTML attribute names warn). To migrate, follow the new error messages — each names the kwarg and the repair.

- **Page titles are declared, not extracted** – `Weft::Page` no longer reads `:title` out of the build attributes; the `title` declaration (above) is the one channel. A `def build` that set `attributes[:title]` before `super` now leaves the tab reading "Weft" (and the string surfaces as a stray `title="..."` HTML attribute on the `<html>` element — the tell that a page still uses the old idiom). To migrate, replace the assignment with a class-body `title "..."`, or the block form where the value came from a lookup.

- **`inline_expand:` fires once** – The preset's default trigger is now `:click_once`, so a repeat click no longer inserts a second copy of the loaded detail. Call sites that hand-wrote `trigger: "click once"` to compensate can drop the override; a call site that genuinely wants re-triggering (a detail that removes itself on close) declares `trigger: :click`.

- **Transfers responses carry the target's companions** – On a `transfers` response, the `includes` declared by the *rendered* component fire — after the swap it's the component in charge — where the transferring component's used to. And `on:` filters now match only the declaring component's own action names: an action arriving via transfer never matches by name (scope those companions with `when: :transferred` instead).

- **The declarer's resolution stays its own** – A transfer target (and a recovery target) resolves from the request and the returned overlay only; the declaring or failing component's defaults and derivations no longer leak across. A target that relied on inheriting another component's *default* for a shared param name now applies its own.

- **Inclusion blocks return deltas, not replacements** – An `includes` block's hash now *adjusts* its companion's picture instead of defining the companion's entire wire: the request universe and the primary's params sit underneath, with the block's keys overlaid. A block that deliberately withheld a key its companion declares should now clear it explicitly (`{ key: nil }`). Blockless inclusions gain the same footing — they now see overlay values (a callable's returned state) they previously missed, and they no longer read the raw request outside the resolution model.

## v0.1.0 (2026-07-12)

First usable release. Weft is component-oriented hypermedia for Ruby: components declare their structure, their data, and their interactive behaviors, and the framework derives the routing, request handling, and client-side wiring automatically.

### New Features:

- **Components and Pages** (`Weft::Component`, `Weft::Page`) – Build HTML in Ruby with a component DSL over Arbre:
  - Describe structure in a `build` block and declare a component's inputs with `attribute` — they arrive from request parameters, coerced to type and filled with your defaults, and reach your code as `attrs.whatever`
  - Render a component as a standalone fragment or drop it into a page through a generated builder method (`builder_method :name`)
  - Pages carry the whole document shell — title, stylesheets, scripts, inline CSS — inheritable down a page hierarchy, so a shared layout costs nothing at each page
- **Interactive Behaviors** – One-line declarations that wire up dynamic behavior, no routes or JavaScript written by hand:
  - `performs :name` – a user-initiated action: run your callable, then re-render the component in place
  - `transfers :name, to: Other` – an action whose response renders a *different* component where the caller was
  - `dismisses :name` – an action that removes the component from the DOM
  - `refreshes every:` / `refreshes on:` – the client re-fetches the component on a timer (whole or fractional seconds, down to a 1ms floor) or whenever a named page event fires
  - `pushes every:` – the server streams re-renders over SSE, with an immediate first frame for every new subscriber
  - `triggers "event"` – announce an action's result to the rest of the page for other components to react to
  - `includes Other` – a companion component rides along out-of-band, updating a second region in the same response
  - `recovers from:, with:` – declare per-class error behavior
- **Automatic Routing** – Every component and page gets a URL with no route table to maintain: components at `/_components/<name>`, pages at name-derived paths, the conventional class-name suffix stripped (`OrdersPanelComponent` and `OrdersPanel`, `DashboardPage` and `Dashboard`, all route without ceremony):
  - Override explicitly with `self.page_path` and `self.component_path =`; tune the component prefix and stream suffix gem-wide
  - Routability is inferred from what a class declares, with `abstract!` / `routable!` to force it either way
  - Every pushing component gets its SSE stream endpoint generated automatically
- **Collision-Safe Routing** – If two routable classes would answer at the same URL, Weft raises `Weft::InvalidDefinition` naming both — on the first request, so you find out immediately. Code reloaders that redefine a class prune the stale registration automatically, and `Weft.registry.clear` gives reload integrations and tests a clean slate
- **Element-Level Wiring** – Attach behavior to any element at any nesting depth with `action:`, `loads:`, `trigger:`, `navigate:`, and `push_url:`, plus `target:` and `swap:` to refine where `loads:` and the shorthands land their response. Raw htmx attributes pass straight through, side by side with what the kwargs expand to
- **Interaction Shorthands** – Named one-word wirings over the `loads:` machinery, with the trigger and swap details baked in: `tooltip:`, `modal:`, `lazy:`, `load_more:`, `infinite_scroll:`, `live_search:`, `tabs:`, `inline_expand:`, and `retry:`. Register your own vocabulary with `Weft.register_shorthand`
- **Semantic Error Handling** – A full error family under `Weft::Error` (`InvalidConfiguration`, `InvalidDefinition`, `InvalidUsage`, and `HTTPError` classes like `Weft::NotFound` and `Weft::Unprocessable`), and a recovery system that renders the right fallback with the right status code:
  - The `recovers` chain renders declared fallbacks with semantic status codes — a validation failure becomes a `422` whose body is the component wearing its error state
  - Recovery targets receive schema-gated context — `:exception`, `:request_path`, `:status_code`, `:component_id`, `:retry_url` — only where they declare it
  - Brand the defaults app-wide via `error_component` / `error_page` / `not_found_page` / `not_found_component`, or override per class with explicit `recovers` declarations
  - The built-in error components offer one-click retry through the `retry:` shorthand
- **Configuration** – `Weft.configure` covers the operational surface: development reloading (`auto_reload`, `reload_paths`), logging (`Weft.logger`, stdout by default; `log_level`, `router_logging`), static asset bundles (`static_assets` with named bundles, path-containment checks, and `assets:` resolution on `register_stylesheet` / `register_script`), htmx delivery (`include_htmx`, `include_sse_ext`), and routing (`component_path`, `stream_suffix`)
- **Secure Script Delivery** – The htmx core and SSE-extension scripts Weft serves are subresource-integrity pinned out of the box, and `register_script` forwards `integrity:` / `crossorigin:` (and any other attributes) to the tag for your own CDN scripts
- **Documentation** – A complete set under `docs/`: a build-your-first-app tutorial; references for the DSL, routing, error handling, configuration, and the Arbre HTML layer; an application-patterns guide (service objects, databases, background jobs, authentication, CSRF, testing); and a twenty-one-page examples catalog with captured wire traffic that deliberately covers the ground of htmx's own examples
- **Demo Application** – A complete Sinatra + Weft application under `demo/`, exercising the feature surface end to end
